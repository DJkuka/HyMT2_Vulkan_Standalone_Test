# Hy-MT2 STQ1_0 CPU — самостоятельный тестовый APK

Отдельное Android-приложение для проверки модели Tencent **Hy-MT2-1.8B-1.25Bit.gguf** на ARM64 CPU. В TapTranslate ничего не встраивается.

## Что тестируем

- Модель STQ1_0 размером 461,860,800 байт (официальный SHA-256 указан ниже).
- Только CPU / ARM NEON: Vulkan выключен при сборке, `gpuLayers=0`.
- 2, 3, 4, 6 или 8 CPU-потоков; исходная настройка — 6.
- Контекст 1024, 2048, 3072 или 4096; исходная настройка — 2048.
- Лимит ответа 256, 512, 768 или 1024 токена; исходная настройка — 768.
- Поле ввода английского текста и вывод перевода на русский.
- Один перевод или серия: один прогрев + три замера.

## Диагностика

В отчёт включаются:
- время загрузки модели и время CPU процесса;
- PSS, RSS, HWM, native heap и Java heap до/после загрузки;
- периодические PSS/RSS-сэмплы во время серии и пиковые значения;
- prompt evaluation time, generation time, tokens generated, tokens/sec;
- wall-clock time и CPU process time на каждый замер;
- доступные частоты CPU-ядер до и после замера;
- Android thermal status, заряд/состояние батареи;
- модель устройства, Android/API, ABI, доступные CPU threads, общий объём RAM;
- native llama.cpp system info;
- средняя, медианная, минимальная и максимальная скорость.

Частоты ядер и некоторые поля памяти зависят от разрешений Android/прошивки и могут отображаться как unavailable. Температура самого кристалла SoC не запрашивается напрямую: используется системный thermal status, если устройство его предоставляет.

Полный отчёт копируется кнопкой внизу экрана. В Logcat используй фильтр `TapSTQ1CPU`.

## Получение модели

Официальный файл:
https://huggingface.co/tencent/Hy-MT2-1.8B-1.25Bit-GGUF/blob/main/Hy-MT2-1.8B-1.25Bit.gguf

- Размер: 461,860,800 байт.
- SHA-256: `cc497fe8f033b52b3b8b00a7669e9661435432f9d4cd43f7ed24400c01507a93`.

Приложение не включает GGUF внутрь APK и не копирует его в приватное хранилище. Оно открывает локальный seekable-файл через SAF и `/proc/self/fd/N`. Для теста выбери файл на SD-карте через системный DocumentsUI. Облачные провайдеры и pipe/stream не поддерживаются.

## Native runtime и сборка

STQ1_0 отсутствует в обычном llama.cpp, поэтому CI собирает собственный CPU-only AAR:
- Android JNI wrapper: `ffmpegkit-maintained/llama-android`, commit `9f5469fd9fa7ea7bc7b01801923af95dc3b41d52`.
- llama.cpp: fork `sjl623/llama.cpp`, PR #22836, commit `1e411d8f5a1e23525fa3265dfb4bd76265465397`.
- STQ1_0 type id: 43.
- ABI: `arm64-v8a`.
- `GGML_VULKAN=OFF`, `GGML_OPENMP=OFF`.

Сборка выполняется через GitHub Actions на ветке `hy-mt2-stq1-cpu-benchmark`. Workflow сначала собирает AAR с STQ1_0, проверяет наличие STQ1_0 кода в ARM64 CPU library и отсутствие Vulkan-библиотек, затем собирает и проверяет APK.

## Первый тест на Lenovo TB128FU / Snapdragon 680

1. Скачай APK и официальный GGUF.
2. В приложении оставь 6 потоков, контекст 2048 и 768 выходных токенов.
3. Выбери GGUF, загрузи модель и дождись результата.
4. Введи один и тот же тестовый фрагмент и нажми «Прогрев + 3 замера».
5. Скопируй полный отчёт и пришли его сюда.
6. Для проверки влияния потоков можно выгрузить модель, выбрать 4 или 8 потоков, снова загрузить и повторить тот же текст.

Для сравнения с текущим Hy-MT2 Q4_K_M используй одинаковый исходный текст, prompt, контекст, лимит выходных токенов, sampling и число потоков. Не сравнивай скорость с разными длинами ответов без учёта tokens generated. Следи за thermal status: после нескольких долгих запусков нагрев может снизить частоты.

## Ограничения

Это экспериментальный benchmark APK, а не новая версия TapTranslate. Сборка подтверждает, что STQ1_0 runtime компилируется и упакован; фактическую загрузку модели, точность и скорость нужно проверить на планшете.
